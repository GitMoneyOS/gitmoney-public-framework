# Private Machine Boundary

## Purpose

Show the open public skeleton without exposing the private machinery.

The GitMoney OS Public Framework is the open-source skeleton and public standard layer. It is not the whole system, not the paid implementation, and not the advanced private method.

The public repository should create trust through inspection and adoption. It should not leak client data, private doctrine, proprietary delivery machinery, credentials, CAC logic, or commercial control systems.

## Public Protocol vs. Private Operator

GitMoney OS separates the operating standard from the intelligence used to install and run advanced implementations.

The public framework teaches:

- what the rooms are;
- how work moves between them;
- how authority is bounded;
- how evidence is recorded;
- how humans approve promotion.

The private system contains:

- diagnosis;
- advanced orchestration;
- specialized skill intelligence;
- client-specific configuration;
- proprietary scoring and decision logic;
- implementation and governance machinery.

You do not need private GitMoney skills to use the public standard.

| Public standard | Private machine |
|---|---|
| Three-layer protocol | Production operator |
| Starter Vault | Private Mothership |
| Public operator skill | Canonical private skills |
| Generic ICM contracts | Client-specific ICM compilers |
| Basic promotion protocol | Advanced promotion intelligence |
| Simple conformance checks | Private diagnostic rubrics |
| Public schemas | Proprietary runtime/state logic |
| Validation scripts | Private orchestration |
| Examples | Client implementation playbooks |

## What is not public

The private machine includes:

- client diagnosis protocols;
- private Identity Forensics Audit templates;
- CAC engine logic and outbound routing;
- private lead evaluation and dispatch systems;
- Mothership governance and executive policy locks;
- private agent orchestration and multi-agent harnesses;
- live client implementation playbooks and delivery runbooks;
- proposal and SOW machinery;
- pricing negotiation notes and internal margin sheets;
- commercial decision systems and private proof gates;
- client-specific evidence, credentials, secrets, or tokens;
- private skill source bytes across all harnesses.

Those materials are not withheld because the public layer is weak. They are withheld because serious infrastructure has boundaries. Not every organ belongs in the showroom.

## Why the boundary matters

> [!WARNING]
> GitHub folder structure is context organization, not a security boundary. Technical permissions, confidential data, and proprietary methods must be protected by distinct technical and legal controls.

The public framework has three jobs:

1. teach the standard;
2. prove the operating logic;
3. create a shared language for serious buyers and builders.

The paid system has different jobs:

1. investigate the client's actual operating constraint;
2. map authority, evidence, context, and handoff failure;
3. design the next intervention;
4. install the private operating architecture when evidence supports a build;
5. maintain governance where the system needs to keep learning.

Confusing those layers weakens both of them. If the open layer exposes too little, the category cannot learn. If the open layer exposes too much, the paid machine becomes undisciplined theater.

## Public-safe examples

A public-safe example may show:

- a fictional company (such as Fictional Studio Co.);
- an anonymized workflow;
- a sanitized issue or PR;
- a general checklist or template;
- an evidence category without private records;
- a clear claim boundary.

## Forbidden examples

A public artifact must never include:

- actual client names, logos, or identifying details without approval;
- raw client screenshots, call transcripts, or operational databases;
- production credentials, access keys, or API tokens;
- private repository URLs or unmerged internal branches;
- confidential commercial margins or internal pricing notes;
- proprietary skill source code from private agent harnesses;
- claims that the evidence does not strictly support.
