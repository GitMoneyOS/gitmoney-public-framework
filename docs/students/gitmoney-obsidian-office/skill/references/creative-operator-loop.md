# Creative Operator Loop

## Purpose

Define the creative production workflow for students using Source Memory and the agent workbench.

## Owner

Red Pillar and Hitsuyo Aku, under KnowTheLedge.

How creative work moves through the Office without dying in a drafts folder.

## The Loop

```text
Spark -> Capture -> Develop -> Blueprint -> Build -> Ship decision -> Evidence -> Next
```

- **Spark:** An idea hits. Do not develop it on the spot.
- **Capture:** One note in `00-inbox/`, standard frontmatter fields plus `created`, back to your day.
- **Develop:** At review, promising sparks move to `20-creative-projects/`. Add contextual links to existing notes.
- **Blueprint:** Before any agent builds anything, write the project blueprint: what it is, who it serves, what done looks like, what is out of scope.
- **Build:** Scoped agent briefs per the workbench contract. One brief per deliverable.
- **Ship decision:** Shipping is an owner decision recorded in `80-decisions/` with an explicit promotion target.
- **Evidence:** The shipped artifact, linked. Screenshots, URLs, or test outputs.
- **Next:** Retrospective notes on what worked and what to reuse. Reusable fragments graduate to `50-sops-and-prompts/`.

## Rules Of The Loop

1. Capture is always allowed; development is scheduled. The inbox protects your focus from your own enthusiasm.
2. Three active creative projects maximum, matching the board WIP limit. The rest wait in Backlog.
3. A creative project with no movement in 30 days gets an owner decision: revive, archive, or hand off.
4. Content derived from a project links back to it. The project is the primary anchor.
5. Completion is defined in the blueprint before the build starts, never renegotiated mid-build.
