# Proof Index

## Purpose

Make the public proof layer inspectable in one centralized location.

A founder should not have to assemble the case from scattered files like an underpaid archaeologist dusting off an operational skeleton. This index maps public claims to inspectable evidence, proof levels, boundary limits, and paid implications.

## Plain-English Job

Map every claim made by the GitMoney OS Public Framework to direct, inspectable GitHub evidence, state what each proof item does not prove, and explain when a serious company needs the paid private machine.

## How to read this

The framework separates three core elements:

1. **Claim:** What the public material can safely assert.
2. **Evidence:** What a reader can inspect in public records.
3. **Boundary:** What the evidence does not prove yet.

A strong proof layer does not make inflated claims. It makes clean, defensible claims.

## Safe claims

GitMoney OS safely asserts that it demonstrates:

- an open AI Office governance pattern;
- live inspectable GitHub evidence (PRs, issues, commits);
- public and private boundary discipline;
- approval packet and decision-grade receipt logic;
- self-audit and continuous remediation workflows;
- plain-language inspection paths for non-technical founders;
- architectural grounding in POL, VSM, ICM, and IFL.

## Claims to avoid

Do not claim GitMoney OS proves:

- formal legal compliance or certification;
- guaranteed financial return or revenue generation;
- complete cybersecurity defense;
- institutional investor diligence readiness;
- acquisition readiness or transaction guarantees;
- production-grade SaaS readiness;
- validated third-party client outcomes;
- fully autonomous operations with zero human judgment.
